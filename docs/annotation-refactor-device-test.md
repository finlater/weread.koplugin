# 统一划线和想法：实机测试

测试分支：`codex/unified-chapter-annotations`。这是 v1.3.1 基础上的测试构建，
尚未作为正式版本发布。安装前退出 KOReader，备份原 `weread.koplugin` 插件目录
和 KOReader 数据目录中的 `weread`。覆盖插件目录后重新启动 KOReader。

## 推荐按顺序验证

1. **单章与快捷动作**：下载一本书的一章，确认下载时只有正文下载确认。
   打开后点击“显示划线和想法”，应直接确认原书绑定，不要求搜索书名。
   匹配后测试菜单、微信读书快捷菜单及手势/按键动作的显示隐藏。
2. **中断恢复**：对较多划线的章节，在下载想法期间暂停，再继续；在匹配期间
   暂停或关书，再打开继续。此前完成的章节和批次不应重拉、重复写入。
3. **同书复用**：同一本书再下载包含该章的选章合集或全书。打开后应复用已保存
   注释，自动生成当前文件的坐标。重点检查划线位置是否正确；单章的 XPointer
   不能直接用于全书。只选第 2、5 章时，不应拉取第 3、4 章。
4. **自动预下载**：为本书启用匹配和下一章预下载，观察下一章正文先可读，再准备
   注释。翻到下一章后应自动匹配；若注释已缓存，断网后打开也可匹配。
   在下载设置关闭“预下载划线和想法”后，正文预下载继续，注释请求停止。
5. **旧书**：打开旧版带划线的 EPUB，已有想法仍可读；完成统一匹配后不应出现
   两条划线或两个弹窗，不要求重新下载正文。另测试以前已绑定的本地书。
6. **样式和边界**：对照旧微信下载书，检查浅色虚线的可读性和醒目程度；检查
   重叠划线、跨行划线、章首、章末、最后一章及含子目录章节。翻页、改变字体和
   字号后，划线应保持位置正确。夜间模式也检查一次。
7. **长书和失败**：长章节同步时尝试暂停，确认界面能响应；同一本长书连续翻页
   检查卡顿。断网/接口失败应保留已完成结果，恢复后继续。正常空章节应显示
   已处理的 0 条结果，不重复要求绑定。

“继续匹配”复用本书缓存；需要从微信获取新数据时，先清理再重新匹配。
本地版本文字差异或目录无法对应会产生未匹配结果，应明确显示数量。

## 反馈信息

请记录设备型号、KOReader 版本、书籍下载形式（单章/合集/全书/本地导入）、
发生问题的步骤和大致时间。样式问题附一张屏幕照片即可；匹配或恢复问题可提供
`crash.log` 中该时间附近含 `annotation_sync` 或 `external_annotation_perf` 的行。
提交日志前删除 Cookie、token、API key 等敏感内容。

本地测试不能证明真机性能改善；重点比较“首章出现结果的时间”“暂停响应”和
“完成后的翻页耗时”。若需回退，退出 KOReader 后恢复备份插件；测试生成的共享
注释库与旧数据库分开保存，必要时可恢复备份的 `weread` 数据目录。
